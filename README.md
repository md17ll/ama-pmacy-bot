# بوت صيدليات عامودا المناوبة

بوت تلغرام عربي لعرض الصيدليات المناوبة في عامودا، مع لوحة إدارة كاملة، استيراد Excel، قراءة صور الجداول بواسطة Gemini، قاعدة PostgreSQL، سجل عمليات، مسودات، نسخ احتياطية، وتنبيه عند قرب انتهاء جدول المناوبات.

## أهم المزايا

### واجهة المستخدم

- الصيدليات المناوبة الآن.
- صيدليات اليوم والغد.
- البحث الذكي عن الصيدلية بالاسم أو اسم بديل.
- عرض الاسم والعنوان ووقت المناوبة بنظام 12 ساعة.
- عرض الوقت المتبقي حتى بداية أو نهاية المناوبة.
- أزرار Inline مرتبة وتعديل نفس الرسالة أثناء التنقل.
- أسماء الأيام والأشهر بالعربية.

### لوحة الإدارة

- إدخال جدول جديد من صورة عبر Gemini أو ملف Excel أو يدوياً.
- حفظ الاستيراد كمسودة قبل النشر.
- معاينة المسودة ومراجعة الأخطاء وإعادة مطابقة الأسماء.
- النشر بالإضافة إلى الموجود أو استبدال الفترة المتداخلة.
- إدارة الصيدليات والعناوين والأسماء البديلة والحالة.
- إدارة المناوبات وإضافتها وتعديلها ونسخها وحذفها.
- فحص التداخلات والأوقات غير الصالحة.
- التراجع عن آخر عملية قابلة للتراجع.
- تصدير الصيدليات والمناوبات إلى Excel.
- نسخة احتياطية JSON.
- إحصائيات المستخدمين وعمليات البحث والأزرار الأكثر استخداماً.
- إدارة الأدمن والصلاحيات.
- إشعار أول دخول لمستخدم جديد.
- تنبيه تلقائي قبل انتهاء جدول المناوبات.

## المتطلبات

- Python 3.12
- Telegram Bot Token
- Gemini API Key
- PostgreSQL على Railway
- حساب GitHub مرتبط بمشروع Railway

## متغيرات البيئة

انسخ أسماء المتغيرات من `.env.example` إلى Railway Variables:

```env
BOT_TOKEN=
GEMINI_API_KEY=
DATABASE_URL=
OWNER_IDS=123456789
TIMEZONE=Asia/Damascus
RUN_MODE=polling
WEBHOOK_BASE_URL=
WEBHOOK_PATH=/telegram/webhook
WEBHOOK_SECRET=
PORT=8080
GEMINI_MODEL=gemini-2.5-flash
LOG_LEVEL=INFO
```

### ملاحظات

- `OWNER_IDS`: رقم Telegram User ID للمالك. يمكن وضع أكثر من رقم مفصول بفواصل.
- `DATABASE_URL`: يتوفر تلقائياً عند إضافة PostgreSQL إلى مشروع Railway وربطه بالخدمة.
- `RUN_MODE=polling`: الأسهل على Railway ولا يحتاج رابطاً عاماً.
- `RUN_MODE=webhook`: يحتاج `WEBHOOK_BASE_URL` و`WEBHOOK_SECRET`.
- لا تضع أي مفتاح سري داخل GitHub.

## النشر على Railway

1. أنشئ مشروع Railway.
2. أضف خدمة PostgreSQL.
3. أضف خدمة من GitHub واختر هذا المستودع.
4. اربط متغير `DATABASE_URL` من خدمة PostgreSQL بخدمة البوت.
5. أضف بقية المتغيرات في Variables.
6. اترك Railway يستخدم `Dockerfile` الموجود في جذر المشروع.
7. راقب Deploy Logs حتى تظهر رسالة بدء polling أو webhook.
8. افتح البوت واضغط Start.
9. افتح `/admin` من حساب المالك.

## تشغيل محلي

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python main.py
```

على Windows:

```powershell
.venv\Scripts\activate
python main.py
```

## الاختبارات

```bash
pip install -r requirements-dev.txt
pytest -q
python -m compileall -q .
```

الاختبارات تشمل:

- قراءة الوقت بنظام 12 و24 ساعة.
- المناوبات التي تتجاوز منتصف الليل.
- الأشهر والأرقام العربية.
- قراءة وإنشاء ملفات Excel.
- اكتشاف التكرار والتداخل.
- صحة callback data وحد Telegram.
- التأكد من ربط كل callback ثابت بمعالج.
- منع ظهور عناصر الهاتف أو الخريطة في الواجهة.

## الأمان

- صلاحيات الأدمن تعتمد على Telegram User ID.
- مفاتيح البوت وGemini محفوظة في Railway Variables فقط.
- نتائج Gemini لا تُنشر مباشرة؛ تُحفظ كمسودة أولاً.
- الحذف والنشر والاستبدال يحتاجان إلى تأكيد.
- العمليات الحساسة تُسجل في Audit Log.
- المالك يُضاف تلقائياً عند بدء البوت من `OWNER_IDS`.
